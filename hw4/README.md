# Домашнее задание № 4. Требования и архитектурное мышление

Архитектурный проект централизованной платформы уведомлений онлайн-банка.

## Содержание

1. [Полная работа](submission.html) — задания 1–8 и шесть встроенных диаграмм; чтение и печать без интернета.
2. [Требования и архитектурное мышление](requirements.md) — задания 1–7.
3. [RFC-001](RFC-001.md) — гарантированная доставка критичных уведомлений с кросс-канальным failover, задание 8.
4. [Диаграммы](diagrams/) — исходники PlantUML и готовые SVG для двух вариантов архитектуры.
5. [Условие задания](assignment.txt).

Отдельный шаблон RFC не приложен; документ содержит все разделы, перечисленные в условии.

## Основное решение

Сравнены собственный автомат доставки на Kafka/PostgreSQL и workflow на Temporal. Выбран Temporal для критичных уведомлений; PostgreSQL хранит состояние и outbox, Kafka разделяет потоки по типам. Расчёты нагрузки, гарантии, ограничения и обоснование выбора приведены в RFC.

## Воспроизведение

Готовые HTML и SVG включены в комплект. Для пересборки нужны Java 21, PlantUML 1.2025.10 и Python 3 с `markdown-it-py==4.2.0`. Диаграммы используют встроенную библиотеку C4 и Smetana, без Graphviz и сетевых подключений.

Из каталога `hw4`, указав путь к PlantUML JAR:

```bash
java -Djava.awt.headless=true -jar /path/to/plantuml.jar -failfast2 -tsvg diagrams/*.puml
python3 scripts/build_submission.py
python3 scripts/check_submission.py
```

Проверка использует стандартную библиотеку Python. Испытания сервисов в RFC описаны как план приёмки будущей реализации.
